# Playlists, clustering & the music graph — page intent map
_Scope: `gui/workspaces/playlists.py`, `gui/workspaces/clustered_enhanced.py`, `gui/workspaces/clustered.py` (dead),
`gui/workspaces/graph.py`, `gui/dialogs/clustering_wizard_dialog.py`, `gui/dialogs/cluster_quality_report_dialog.py`,
`gui/widgets/interactive_scatter_plot.py`, `gui/widgets/interactive_3d_scatter.py` (dead), `gui/widgets/cluster_legend.py`,
`gui/widgets/track_details_panel.py`; backend `playlist_generator.py`, `playlist_engine.py`, `clustered_playlists.py`,
`cluster_graph_data.py`, `cluster_graph_3d.py`, `cluster_graph_panel.py` (Tkinter-only); `docs/features/playlists_and_clustering.md`.
Date: 2026-11-07._

## Summary
This area turns a library into things you can listen to. You can build playlists by rule (one per folder, tempo/energy
buckets, or an Auto-DJ chain from a seed track), or let the app analyse the audio and group tracks that sound alike
(clustering). You can then explore those groups on a 2-D map, select a region, and play it or export it as a playlist.
Today that journey is split across three sidebar pages (Playlists, Clustered, Music Graph, Ctrl+7/8/9), plus a wizard
dialog, a quality-report dialog and a browser-based 3-D page. The handoffs between them are weak. The clustering engine
never writes cluster playlists, although several pieces of UI and the docs say it does. The graph doesn't reload after a
clustering run. The wizard drops every choice the user makes. The quality report renders empty.
The data layer (`cluster_graph_data`) and the 2-D map widgets are the healthiest part of the area.

**Environment note for the harness:** in this container `pyqtgraph 0.14.0` is installed without its required `colorama`
dependency, so `import pyqtgraph` fails. The Graph page then shows "PyQtGraph is not installed", which is misleading.
I stubbed `colorama` in-process for my probes. (I briefly `pip install`ed colorama and uninstalled it again, so the
environment is back as I found it.) `hdbscan`, `librosa` and `umap` are also absent, so the real clustering, tempo and
Auto-DJ paths cannot run here.

## Sound Map now: the Liquid Glass restyle (R2, 2026-11-08)

The audit below describes the pages as they were found. Clustered and Music Graph have since become the
**Sound Map** page (Analyse · Map sections) and most of the bugs are fixed (see "Bugs found"). In R2 the Sound Map's
contents moved onto the glass design system; `docs/gui_inventory.md` §6.8, §7.2, §7.3 and §7.6 have the details.

- **Analyse** (`clustered_enhanced.py`): no repeated page title; one muted intro line and three cards.
  - *Quick Start* is the hero card (`headerCard`): the fixed settings in one line, **Run Quick Start** (primary) and
    **Guided setup…** (the wizard).
  - *Results* shows an `EmptyState` before the first run, progress and Cancel during one, then a `StatRow`
    (Clusters, Tracks, Unclustered, Not analysed, Silhouette toned good / fair / poor) with **Open the map**,
    **Save cluster playlists…** (the page flow, mirrored) and **Quality report**.
  - *Your own settings* replaces the read-only config text: the six `FEATURE_ORDER` blocks as pill toggles, the
    algorithm and its parameters, the scaling and the playlist offer, all editable, and **Run with these settings**.
    The wizard is now a guided way to fill this card in (it opens on the card's values and writes back), which
    answers the "one form with presets" note above without removing the wizard.
- **Map** (`graph.py`): the map is the hero card. Pan / Box / Lasso is a segmented control whose chosen mode is
  raised (it used to look unchecked); Fit, Clear and Reload are glyph icon pills; the selection bar sits above the
  plot so Play / Export stay in view. The legend and track details are glass side cards that move below the map in a
  narrow window (no horizontal scroll at 900 px).
- **Plot** (`interactive_scatter_plot.py`): no more opaque dark box. A transparent PyQtGraph view on the material's
  well, a faint grid that moves with pan and zoom, and points as a vivid core with a soft ring. Each cluster has one
  radial-gradient brush, so PyQtGraph's symbol atlas renders one sprite per cluster and every point is a cached pixmap
  fragment (no per-point effects). Selection rings in the accent and dims the rest with a single item opacity; hover
  is a one-point ring layer; the marquee is a dashed accent line. A theme switch repaints the well, grid and rings but
  never re-sends the points. Measured with `FrameGapMeter` over pan, zoom and hover on 5,000 points: max ~30 ms,
  p95 ~18 ms offscreen (`tests/ui/test_ui_sound_map_glass.py`).
- **Legend and details** (`cluster_legend.py`, `track_details_panel.py`): glass rows whose colour dot is the
  show/hide toggle (no per-row style sheets); an empty state, a rounded cover or music glyph, title / artist / album,
  a genre / year / cluster strip, a middle-elided path and Play / Open folder.
- **Dialogs**: the wizard has step pills that track the real step and a glass card per step; the quality report's
  sections are `GlassCard`s (they used to be plain frames named `workspaceCard`) with a toned `StatRow`; the cluster
  playlists preview puts options and table in one glass card, 34 px rows without grid lines, round colour dots and a
  warnings well.

## Pages

### Playlist Generator (`gui/workspaces/playlists.py`, class `PlaylistsWorkspace`)
- **Intent:** write `.m3u` playlists by simple rules (folder, tempo/energy bucket, Auto-DJ chain) and repair existing playlists whose paths broke.
- **When the user comes here / entry points:** sidebar key `playlists` ("Playlists", 🎵), Ctrl+7. Nothing else navigates here.
- **Primary flow:** pick one of four tabs → (optional) set output folder / seed / track count / playlist list → click the tab's primary button → worker runs → log lines → done. **No preview and no confirmation at any point.** Every mode writes (or overwrites) `.m3u` files directly.
  1. *Folder Playlists*: `playlist_generator.generate_playlists({p: p}, lib, output_dir)`. This makes one playlist per **leaf folder** (album), not per artist as the subtitle says. Reserved folders (Docs/Trash/Quarantine/Not Sorted/Playlists) are included (PL-12).
  2. *Tempo / Energy*: `playlist_engine.bucket_by_tempo_energy` → `write_playlist` per `slow|medium|fast × low|medium|high` bucket into `<lib>/Playlists/`. The range spinboxes are decorative (PL-14).
  3. *Auto-DJ*: `autodj_playlist(seed, all_tracks, n)` → always `<lib>/Playlists/autodj.m3u` (silently overwritten; the output folder is ignored).
  4. *Playlist Repair*: user-added `.m3u` list + "Prefer Opus" (decorative). With a list it is a **no-op that logs success** (PL-10). With an empty list it rewrites every playlist under `<lib>/Playlists/` in place using fuzzy matches (PL-11).
- **Reads / writes:** `<lib>/Playlists/*.m3u`, `<lib>/Playlists/autodj.m3u`, `<lib>/Docs/tempo_energy.npy` (pickle cache), playlists anywhere the user picks. No config keys. Signals out: `log_message`, `status_changed`.
- **Backend dependencies:** `playlist_generator.generate_playlists / write_playlist / update_playlists`, `playlist_engine.bucket_by_tempo_energy / autodj_playlist` (→ `clustered_playlists.extract_audio_features`, which hard-imports `hdbscan` and needs `librosa`). All run on `PlaylistWorker` (QThread). Writes happen on the worker thread.
- **State owned:** `_worker`, the repair list, form fields. Nothing resets on library change (no `_on_library_changed`).
- **Async model:** one `PlaylistWorker` per click. No Cancel button (`cancel()` exists but nothing calls it), no progress beyond an indeterminate bar, and buttons are never disabled. **A second click while running drops the only reference to the running QThread → `QThread: Destroyed while thread is still running` → abort (exit 134)** (PL-01). Closing the app mid-run aborts the same way (PL-02). Navigating away is harmless.
- **Motion & visuals:** none. Inline `font-family: Consolas` on the log. Emoji in button labels.
- **Decorative / dead controls:** Tempo range min/max and Energy range min/max (`_tempo_min/_tempo_max/_energy_min/_energy_max`, passed into `PlaylistWorker.tempo_range/energy_range` and never read). "Prefer Opus when searching for missing FLAC" (`_prefer_opus_cb`, never read; the legacy `PlaylistRepairDialog` in `main_gui.py:6725` did use it). The Output folder only affects Folder mode.
- **Overlaps:** the log card duplicates the global Log drawer (each line goes to both). Graph's "Export playlist…" is a fourth way to write an m3u. Genre playlists (`sort_tracks_by_genre`/`export_genre_playlists`) and "More like this" exist in the backend but are only reachable in the legacy Tk app.
- **Redesign notes:** this page needs the same "scan → preview → write" contract as the rest of the app: show the buckets / chain / repaired lines, with a diff of any playlist that would be overwritten, then write. Repair should port the legacy per-playlist algorithm (opus/flac swap + search index, with a report), not call `update_playlists`. Auto-DJ should let you pick the seed from the library (or from the Player / Graph) and choose the output name. Range fields should either filter or disappear. Reserved folders must be skipped.
- **Testability seams:** patch `playlist_engine.bucket_by_tempo_energy`, `playlist_engine.autodj_playlist`, `playlist_generator.*` (imported inside `run()`, so patching the module attribute works). Patch `QFileDialog.getOpenFileNames/getExistingDirectory/getOpenFileName` and `QMessageBox.warning` (no-library path). Latch onto `_worker`, `_log_area`, `_prog_bar`, `_repair_list`, `_autodj_seed`, `_autodj_count`, `_folder_out_entry`. Tests must `wait()` the worker before teardown, or the process aborts.

### Clustered Playlists (`gui/workspaces/clustered_enhanced.py`, class `EnhancedClusteredWorkspace`, registered as `"clustered"`)
- **Intent:** analyse the library's audio, group similar tracks (K-Means/HDBSCAN), judge the grouping, and hand it to the map.
- **When the user comes here / entry points:** sidebar `clustered` ("Clustered", 📊), Ctrl+8. Nothing navigates here (the Graph's empty state says "Run Clustered Playlists first" as text only).
- **Primary flow:** three tabs.
  1. *Quick Start*: one button → fixed config (K-Means k=8, features tempo+mfcc+energy, standard scaling).
  2. *Advanced*: "Configure with Wizard…" → `ClusteringWizardDialog.exec()` → config summary text → "▶ Run". (The wizard's settings are lost, PL-03/PL-04.)
  3. *Results* (auto-selected on run): progress bar, status, log, Cancel → on finish, a summary card (clusters, tracks, silhouette) and buttons: "View Quality Report" (dialog), "View Playlists" (`xdg-open <lib>/Playlists`), "Open Visual Graph" (`navigate_requested("graph")`).
  There is **no preview/confirm**. It writes only analysis artefacts (no audio files), so the risk is low, but it silently overwrites `Docs/cluster_info.json` and `Docs/cluster_graph.html` from the previous run.
- **Reads / writes:** `<lib>/Docs/features*.npy` + `_metadata.json` (pickle cache keyed by selection+engine), `<lib>/Docs/cluster_info.json`, `<lib>/Docs/cluster_graph.html`. **No playlists are written** (`clustered_playlists.py:831` "Automatic playlist export disabled"). Signals out: `log_message`, `status_changed`, `navigate_requested("graph")`. Doesn't use `log_message` for worker lines (only its own log area).
- **Backend dependencies:** `clustered_playlists.generate_clustered_playlists(..., engine="parallel", use_max_workers=True)`. It runs on `ClusterWorker` (QThread), which in turn spawns a `ProcessPoolExecutor` (cpu_count-1 processes). Afterwards come t-SNE/UMAP 2-D and 3-D embeddings and sklearn metrics, also on the worker.
- **State owned:** `_worker`, `_current_config` (wizard or last-run config), `_current_result` (full numpy result, kept in memory until the next run). Not reset on library change (PL-31).
- **Async model:** a progress signal exists, but it jumps 0→5→10→90→100. Nothing reports during extraction, the long part. Cancel only sets a flag that is checked during `os.walk` and **after** the backend returns. The run continues to completion, writes all artefacts, and log lines are suppressed after Cancel, so the page looks frozen (PL-09). Run buttons stay enabled. A second run calls `_cleanup_worker()` on the GUI thread, which blocks up to 5 s and then calls `QThread.terminate()` (PL-08). A previous worker's queued `finished` can arrive after the new worker starts and calls `new_worker.wait()`, which freezes the GUI for the whole new run (PL-07). `closeEvent` never fires for a stacked child, so closing the app mid-run aborts (PL-02). Navigating away mid-run is fine.
- **Motion & visuals:** none beyond widgets created and destroyed with `deleteLater`. Hard-coded colours: `#666` status, `#ef4444` error, `#22c55e` success, `font-size:10px` monospace log.
- **Decorative / dead controls:** Quick Start's info text promises "All features (tempo, timbre, harmony, energy)", but chroma is off. The config summary lists "Create playlists / Generate quality report / Open interactive graph", but the worker ignores all three: no playlists are written, the report button depends only on whether metrics exist, and the graph is never opened automatically. "View Playlists" opens a folder that contains no cluster playlists (and only works where `xdg-open` exists).
- **Overlaps:** the "Open 3D view" output is also reachable from the Graph page. The quality numbers also appear in the summary card.
- **Redesign notes:** this page is really step 1 of "Explore my library as a map". Merging it into the Graph page as an "Analyse / Re-analyse" side sheet would remove the empty-graph dead end and the manual Reload. Quick Start vs Advanced+wizard should become one form with presets (the wizard is five pages for about eight values). Real progress, per-file counts, and real cancellation (a cancel event threaded through the extraction loop and the process pool) are prerequisites for a polished feel. "Cluster → playlists" needs an explicit, previewed export step (per-cluster names, checkboxes), probably on the map.
- **Testability seams:** inject a fake `clustered_playlists` module in `sys.modules` (the worker imports inside `run()`). It must return `{"X","labels","tracks","cluster_info"}`. Patch `QMessageBox.warning`, `ClusteringWizardDialog.exec`/`get_config`, `ClusterQualityReportDialog.exec`, and `subprocess.Popen` (View Playlists). Latch onto `_tab_widget`, `_results_layout` (inspect child QLabels), `_progress_bar`, `_progress_status`, `_log_area`, `_config_display`, `_worker`. There are no objectNames. Always drain the worker; never let a test start two runs without draining.

### Clustering Configuration Wizard (`gui/dialogs/clustering_wizard_dialog.py`, class `ClusteringWizardDialog`)
- **Intent:** let a non-expert choose features, scaling, algorithm and parameters in plain steps.
- **When the user comes here / entry points:** Clustered → Advanced → "⚙ Configure with Wizard…" (modal `exec()`).
- **Primary flow:** 5 pages (Features with Fast/Balanced/Complete presets → Normalization & reduction → Algorithm + K or min size/min samples → Post-processing → Output) → Finish = `accept()`. The caller reads `get_config()`.
- **Reads / writes:** an in-memory `config` dict only. No persistence; each opening starts from defaults.
- **Backend dependencies:** none.
- **State owned:** `config`, `_current_step`.
- **Async model:** n/a (modal). A `QMessageBox.warning` fires if no feature is ticked. That check runs when step 0 is *entered*, so the user sees it on returning to page 1, not on leaving it.
- **Motion & visuals:** a 4-px step progress bar. Many inline `color:#666; font-size:10px` labels.
- **Decorative / dead controls:** "Dimensionality Reduction" combo, the `eps` default, "Remove clusters smaller than threshold" + its spinbox, "Merge small clusters into 'Miscellaneous'", "Create M3U playlists", "Generate cluster quality report", "Open interactive graph". None of these are read downstream. **And because of PL-03, even the live controls (features, normalization, algorithm, K, min sizes) never reach the config.**
- **Overlaps:** duplicates the Quick Start config.
- **Redesign notes:** collapse into a single "Analysis settings" panel with presets and an "advanced" disclosure. Persist the last-used settings via `config.save_config`. Show estimated cost ("onset rate: slow"). Remove the post-processing and output pages until they exist.
- **Testability seams:** construct directly, then drive `_feature_checkboxes`, `_norm_combo`, `_algo_combo`, `_k_spinbox`, `_min_size_spinbox`, `_min_samples_spinbox`, `_on_next()`, `_on_prev()`, `get_config()`. Patch `QMessageBox.warning`.

### Cluster Quality Report (`gui/dialogs/cluster_quality_report_dialog.py`, class `ClusterQualityReportDialog`)
- **Intent:** explain whether the grouping is trustworthy (silhouette / Davies-Bouldin / Calinski-Harabasz, per-cluster sizes, suggestions).
- **When the user comes here / entry points:** Clustered → Results → "📄 View Quality Report" (shown only when metrics were computed).
- **Primary flow:** read-only modal → Close.
- **Reads / writes:** `metrics` and `cluster_info` from the in-memory result. Per-cluster `genres` are always `[]` and `tempo` is `[0,0]` from the backend, while the dialog looks for `tempo_range` and `silhouette`. So per-cluster cards can only ever show "Size".
- **Backend dependencies:** none (numpy imported, unused).
- **State owned:** none.
- **Async model:** n/a.
- **Motion & visuals:** **renders empty.** `_create_card` installs a layout on the card, then each section calls `QVBoxLayout(card)` again ("QLayout: Attempting to add QLayout … which already has a layout"). Every metric row, cluster card and suggestion goes into an orphan layout. On screen there are only three titled white boxes (PL-05). The selector-less `setStyleSheet("border…; background-color:#fafafa")` gives every child label a border and a light background, which is unreadable in dark themes (PL-23).
- **Decorative / dead controls:** effectively the whole body.
- **Overlaps:** the summary card on the Results tab shows the silhouette too.
- **Redesign notes:** fold into the analysis results as an inline "Quality" card with plain-language verdicts. Exclude noise from metrics.
- **Testability seams:** construct with a metrics dict and assert child QLabels are *visible* (`isVisibleTo(dialog)`), which catches the orphan-layout bug. Grab-to-PNG works offscreen.

### Visual Music Graph (`gui/workspaces/graph.py`, class `GraphWorkspace`)
- **Intent:** see the clustered library as a map, find a region that sounds alike, and play it or save it as a playlist.
- **When the user comes here / entry points:** sidebar `graph` ("Music Graph", 🌐), Ctrl+9, Clustered → Results → "Open Visual Graph" (`navigate_requested`).
- **Primary flow:**
  1. Data loads from `<lib>/Docs/cluster_info.json` via `cluster_graph_data.load_cluster_data` + `graph_points`. This happens on construction (empty library → "No library selected."), on library change, and on "↻ Reload". **It does not reload on navigation**, so right after a clustering run it still says "No cluster data … Run Clustered Playlists first" (PL-06).
  2. Choose Pan / Rectangle / Lasso (Ctrl/Shift adds to the selection). Hover shows a tooltip and fills the details panel without disk I/O. Click reads tags and cover art (`read_metadata`) on the GUI thread.
  3. Legend: per-cluster checkbox hides/shows; clicking a row selects the cluster; Show all / Hide all.
  4. Selection bar: "▶ Play selection" → `play_tracks_requested(paths, "Music Graph selection")` → main window → Player. "Export CSV…" / "Export playlist…" → `QFileDialog.getSaveFileName` (that file dialog is the confirmation) → write.
  5. "Open 3D view" → `cluster_graph_3d.generate_cluster_graph_html` (only if the HTML is missing) → `webbrowser.open`. The page needs three.js from cdnjs, so offline it is blank.
- **Reads / writes:** reads `Docs/cluster_info.json` and `Docs/cluster_graph.html`. Writes user-chosen CSV/M3U and possibly `Docs/cluster_graph.html`. Signals out: `play_tracks_requested`, `log_message`.
- **Backend dependencies:** `cluster_graph_data` (Qt-free, tested), `cluster_graph_3d`, `utils.audio_metadata_reader.read_metadata`. All on the GUI thread: JSON parse plus `set_data` takes about 0.27 s at 5 000 points and about 1.1 s at 20 000.
- **State owned:** `_xy/_labels/_tracks/_metadata` (until the next reload), the plot's selection and per-cluster visibility, and the legend's visibility. Visibility persists across reloads **and library switches** (minor), and the selection is cleared on reload.
- **Async model:** none. Everything is synchronous. A failed reload leaves the previous plot and legend drawn and clickable while the toolbar is disabled and the status shows the error (PL-22).
- **Motion & visuals:** pyqtgraph scatter; marquee `QGraphicsPathItem` (blue, 40-alpha fill); selected points get size 13 and a white pen. The plot background is taken once from `palette().base()` at construction and never updated, so it stays wrong after a theme switch (white plot inside a dark app, and the white selection pen is invisible on light) (PL-21). The legend's scroll area gets squeezed to about two rows in the side column. Mode toggle buttons don't look checked.
- **Decorative / dead controls:** none found (all wired). "Open folder" works on Win/macOS/Linux.
- **Overlaps:** the 3-D browser page has its own legend, selection and CSV/M3U export. The Player is the play target.
- **Redesign notes:** make this the home of the whole "explore" journey: an empty state with a primary "Analyse my library" action (runs the clustering inline with progress), automatic reload when new data lands (file watcher or a signal from the analysis), and a selection tray that previews the tracks before Play or Save. Add a per-cluster "Save as playlist" with a preview. Keep hover and selection separate in the details panel (PL-19). Move JSON parsing off the GUI thread for large payloads. Theme the plot from tokens.
- **Testability seams:** fabricate payloads by writing `Docs/cluster_info.json` in a `tmp_path` library and calling `set_library_path` / `reload_data()`. Read `_status.text()`, `_sel_label.text()`, `_play_btn.isEnabled()`, `_plot.scatter.data` (rendered spots), `_plot.get_selection()`, `_legend._rows[cid].checkbox`. Patch `QFileDialog.getSaveFileName`, `webbrowser.open`, `subprocess.Popen`/`os.startfile`, `read_metadata` (avoids disk). Connect to `play_tracks_requested`. **pyqtgraph drags can't be driven with `QTest.mouseMove`** (no buttons held, so no drag). Call `_plot._on_drag_started/_moved/_finished` or the ViewBox `drag_*` signals instead, or send hand-built `QMouseEvent`s with buttons. Requires an importable pyqtgraph (and therefore colorama).

## Cross-page relationships
- **Intended journey:** "I want playlists" → *either* rule-based (Playlists page, terminal: m3u files on disk) *or* similarity-based: Clustered (analyse) → Results → "Open Visual Graph" → Graph (explore, lasso) → "Play selection" → `play_tracks_requested` → `AlphaDEXWindow.play_tracks` → Player `load_tracks_and_play`. You can also take "Export playlist…" to a `.m3u` in `<lib>/Playlists`.
- **Data handoff Clustered → Graph** is purely through `Docs/cluster_info.json` on disk. No signal says "new data", and Graph only reloads on library change or the manual Reload, so the handoff is broken in practice (PL-06).
- **Auto-DJ ↔ clustering:** Auto-DJ silently depends on `clustered_playlists` (and so on `hdbscan` + `librosa`). It doesn't use the clustering feature cache, so it re-extracts the whole library every run.
- **Playlists → Player:** none. Generated playlists can't be played from here. Player is reached only from the Graph.
- **Library change:** Graph reloads. Playlists and Clustered keep stale state (Clustered shows the previous library's results).
- **Outside the area:** Genres page (genre tag-fill/normalize) feeds genre information that playlist building could use, but no Qt playlist mode reads genre. The Indexer's move map was the original input of `generate_playlists(moves, …)`, and the Qt Folder mode fakes it with `{p: p}`.
- **Should they merge?** Yes, partly. Clustered + Graph (+ the wizard and report) belong in one "Explore / Sound Map" page: analyse → map → selection → play/save, with quality as an inline card. The rule-based Playlist Generator is a different mental model and can stay separate, but it should gain a preview list, a "send to Player" action, and a shared "save playlist" sheet with the Graph.
