Design consistency audit · Qt app

AlphaDEX has a design system.
Three pages use it.

Every screen in the PySide6 app was launched, screenshotted in both the default dark (Midnight) and light (Pearl) themes, and read against its source. The finding is not that the app lacks a visual language — it ships a thorough one. It is that the language is optional, and most screens declined it.

The verdict

Read this part and you can skip the rest.

AlphaDEX already has a real design system. gui/themes/ defines 14 complete themes as frozen token dataclasses, a 39 KB QProxyStyle that hand-paints every control, a point-based TypeScale, and a QSS layer exposing a 15-name component vocabulary (workspaceCard, headerCard, actionCard, workflowStepper, sectionTitle, cardTitle …). It is genuinely good work. When a page uses it, that page themes correctly across all 14 themes for free.

The system is opt-in, and opting out is easier. WorkspaceBase offers helpers — _make_card(), _make_card_title(), _make_primary_button() — but nothing requires them, and no token object is reachable from a workspace without importing the manager by hand. So the path of least resistance is setStyleSheet("color: #64748b"). Twelve of fourteen workspaces took it.

The result is four visual languages in one binary. A hero-card-and-stepper language (Indexer, Duplicates, Library Sync); a bare-title-and-loose-controls language (most of the rest); a tile-and-status-pill language (Utilities); and a full-bleed application chrome language (Player). Plus gui/qt_launcher.py — 698 lines and the single densest concentration of hardcoded styling in the tree — which the active app never loads at all.

The fix is not a redesign. The target already exists on screen: the Indexer page. The work is closing the escape hatches so the system is the only convenient path, then migrating eleven pages onto it. Sequence in the migration plan.

Defects, not taste

Eight of these are wrong by any style guide. They surfaced while capturing the screenshots — three of them prevented capture entirely until fixed. Each is small; each has a named fix and a line number.

D1Every tab label and every group-box title fails to paintcrash

gui/themes/style.py:537 · gui/themes/style.py:554

The custom style engine asks for a font weight that does not exist in Qt 6. Qt's enum is DemiBold; there is no SemiBold member in PySide6 or PySide2. The AttributeError is raised inside a paint override, so Qt swallows it and abandons that draw call — the label is simply never rendered.

# CE_TabBarTabLabel — raises on every selected tab repaint
if active:
    font.setWeight(QtGui.QFont.Weight.SemiBold)   # AttributeError: SemiBold

This hits the three tabbed workspaces (Genre Normalizer, Playlists, Clustered) and the Settings dialog, plus every QGroupBox title in the app. While capturing, it aborted widget.grab() outright — those three pages could not be screenshotted until it was corrected.

Fix — SemiBold → DemiBold at both sites. Applied in this branch so the remaining pages could be captured.
D2The Pair Review dialog cannot opencrash

gui/dialogs/pair_review_dialog.py:355–358

Four shortcut constructions use the Qt 5 namespace. QShortcut moved from QtWidgets to QtGui in Qt 6, so the constructor raises before the dialog finishes building. Every other file in the tree — main_window.py:221, player.py:953 — already uses the correct namespace, so this is an isolated miss.

QtWidgets.QShortcut(QtGui.QKeySequence(Qt.Key.Key_Return), self, self._handle_yes)
# AttributeError: module 'PySide6.QtWidgets' has no attribute 'QShortcut'
Fix — QtWidgets.QShortcut → QtGui.QShortcut ×4. Applied in this branch; the dialog then opens and is captured below.
D3The Cluster Quality Report renders white-on-whiteunusable

gui/dialogs/cluster_quality_report_dialog.py:171, 192, 208

This dialog styles itself for a light theme that the app does not ship as default. It paints card backgrounds #fafafa and body copy #333, while text it does not override inherits the active theme's near-white. On Midnight — the default — the metric values, the per-cluster cards and the suggestions are all invisible.

card.setStyleSheet("border: 1px solid #ddd; border-radius: 4px; background-color: #fafafa;")
suggestion_widget.setStyleSheet("color: #333; font-size: 11px;")

There is a compounding Qt subtlety: a border declared on a bare container QWidget cascades to every child widget, which is why the labels inside also pick up boxes they were never meant to have.

Fix — delete all three stylesheets and give the container setObjectName("workspaceCard"). The theme QSS then supplies background, border and radius correctly in all 14 themes.
D4The sidebar wordmark disappears in all six light themescontrast

gui/widgets/sidebar.py:139–142

“AlphaDEX” at the top of the nav rail is pinned to #f8fafc — near-white. Pearl's sidebar is #f0f2f8. The app's own name is the least legible text on the screen in half its themes. Visible in the light captures throughout this report.

logo_lbl.setStyleSheet(
    "color: #f8fafc;" # ← ignores sidebar_text; invisible on 6 of 14 themes
    "font-size: 22px; font-weight: 700; padding: 0 8px; letter-spacing: -0.02em;")
Fix — drive the colour from tokens.sidebar_text and repaint on theme_changed, as Sidebar already does for its nav buttons.
D5Light-theme names are unreadable in the theme pickercontrast

gui/themes/picker.py:115

Each swatch previews its own theme, then writes that theme's name using the currently active theme's text colour. Browsing from a dark theme, every light swatch label — Pearl, Blossom, Meadow, Lavender, Sunset — is white on white. You cannot read the name of the theme you are about to pick.

p.setPen(QtGui.QColor(current.text_primary))   # active theme's ink…
p.drawText(label_rect, Qt.AlignmentFlag.AlignCenter, t.name)  # …on swatch t's ground
Fix — current.text_primary → t.text_primary. One word; the swatch then labels itself in its own palette.
D6The Player keeps a dark slab in light themestheming

gui/workspaces/player.py — 16 setStyleSheet calls, 16 hardcoded colors, 0 token reads

The Player is the largest workspace (1,980 lines) and reads the theme zero times. Its track table, column header, album-art placeholders and separators are fixed to Midnight values (#30363d, #8b949e, #64748b). Switch to Pearl and the page keeps a black rectangle across two-thirds of the window. Side-by-side capture in the Player section.

Fix — the largest single migration in the app; scheduled as its own phase in the plan rather than bundled with the quick wins.
D7Library Sync overflows its viewport horizontallylayout

gui/workspaces/library_sync.py

At the app's own default window size (1300×860) and at the 1440×900 used for capture, the Library Sync content is wider than the content area: the “Browse…” buttons on both path rows are clipped to “Bro”, and a horizontal scrollbar appears under the workspace. The path QLineEdits carry no width constraint, so they win the layout negotiation against the buttons beside them.

Fix — give the path rows a minimum-width budget and let the line edit shrink — the shared _make_browse_row() helper in base.py already fixes the browse button at 80 px for exactly this reason; this page builds its rows by hand instead.
D8The landing wordmark is clipped on both sideslayout

gui/widgets/landing.py

The first thing the app shows renders “AlphaDEX” as “lphaDE” — the A and X are cut by the CTA card's fixed width. It is the first frame of the product and it clips the product's name. See Landing.

Fix — size the card to the laid-out text, or reduce the wordmark point size until fontMetrics().horizontalAdvance() fits with padding.

Inconsistency catalog

Six axes on which the app disagrees with itself. These are the decisions the standard has to settle.

C1Page headers — three patterns

How a workspace introduces itself is the most visible inconsistency, because it is the first thing on every screen.

  • Hero card + stepper — title and description inside a headerCard with a 3 px accent left border, followed by a workflowStepper rail reading 1. Preview (dry run) → 2. Review HTML report → 3. Execute changes. Used by Indexer, Duplicates, Library Sync.
  • Bare title — a sectionTitle label and a sectionSubtitle sitting directly on the background with no container. Used by Compression, Similarity, Tag Fixer, Genre Normalizer, Playlists, Clustered, Music Graph, Utilities — eight pages.
  • Application toolbar — title inline in a control strip with a search field and buttons; no subtitle, no card. Used by Player.

Help is a fourth case: bare title with no subtitle at all.

C2Progress through a workflow — three idioms

Three screens teach the user three different ways to read “where am I in this process”.

  • Inline stepper rail — 1. Scan & fingerprint → 2. Review groups → 3. Execute plan, active step in accent, rest muted. Indexer, Duplicates, Library Sync.
  • Numbered card headings — 1 · Collect the raw genres, 2 · Build the mapping, 3 · Preview what would change as the titles of stacked cards. Genre Normalizer only.
  • Wizard counter + progress bar — Step 1: Feature Selection with 1 of 5 and a green bar. Clustering Wizard dialog only — and the bar is green while the app's accent is blue.

Separately, the Indexer's Progress card uses a fourth vocabulary — Phase A / Phase B / Phase C — for the same underlying run it describes as steps 1–3 in its own stepper.

C3Buttons — a three-name vocabulary, thinly used

The style engine recognises exactly three semantic buttons by objectName — primaryBtn, dangerBtn, successBtn — and paints everything else as a neutral card-coloured button. There is no secondary, ghost, or toolbar variant, so any page wanting one invents it.

The consequential disagreement is which colour means “commit”:

  • Duplicates commits with a red Execute button — destructive framing.
  • Tag Fixer commits with a green Apply Selected button — confirmation framing.

Both write to the user's library. A user who learns one page is primed wrongly for the other. Grouping is also unsettled: Indexer and Duplicates put actions in a bordered actionCard; Tag Fixer, Similarity and Compression leave the same buttons floating loose between cards.

Icon convention is a third axis — Duplicates ships 🔍 Scan Library / ▶ Execute with emoji baked into the label string, Compression ships 🔍 Estimate Space Savings, while Help, Graph and Playlists use bare text. Clustered puts emoji in its tab labels (🚀 Quick Start); Genre Normalizer and Playlists do not.

C4Colour — the token file is bypassed 54 times

Outside tokens.py, the active app hardcodes 54 distinct colours. Three clusters matter:

  • The status triple is copy-pasted into 11 files. #22c55e / #f59e0b / #ef4444 appear across Duplicates, Library Sync, Tag Fixer, Genres, Similarity, Playlists, Clustered, Indexer, Tools, and two dialogs. Those are exactly the dark defaults from tokens._d(). Every light theme defines different ones — #16a34a / #d97706 / #dc2626 — so all 11 files are wrong in all 6 light themes.
  • #64748b is used 23 times and is not a token in any theme. It is Tailwind's slate-500, standing in for secondary text where text_secondary or text_muted belongs. Four more off-palette greys (#f8fafc, #818cf8, #e2e8f0, #1e2130) appear the same way.
  • The root cause is an API shape. WorkspaceBase.status_changed = Signal(str, str) takes a colour string as its second argument, so every caller must hardcode a hex to emit a status at all.
# duplicates.py:482, 590, 596 — the signal's contract forces this
self.status_changed.emit("Scanning…",     "#f59e0b")
self.status_changed.emit("Scan complete", "#22c55e")
self.status_changed.emit("Error",         "#ef4444")
Fix — change the second argument to a semantic level — "busy" / "ok" / "error" — and let the log drawer resolve it against the live tokens. This deletes roughly 30 hardcoded colours by changing one signature.
#22c55esuccess · dark
#16a34asuccess · light
#f59e0bwarning · dark

#dc2626danger · light

C5Typography — two systems, different units, one wins by accident

gui/fonts/loader.py defines a complete TypeScale: named roles (SECTION_HDR, BODY, LABEL, SMALL, NAV_ITEM, BUTTON…), six weights and three letter-spacing steps, all in points. Nothing outside the theme engine imports it. No workspace, no dialog, no widget.

Meanwhile the app carries 68 hardcoded font-size declarations in pixels across ten distinct values — 9, 10, 11, 12, 13, 14, 15, 16, 18 and 22 px. Because a widget stylesheet beats the font applied in polish(), the ad-hoc px values silently win wherever they appear.

Font families are bypassed the same way: UI_STACK and MONO_STACK name Inter and JetBrains Mono, but eight files hardcode font-family: 'Consolas', monospace for their log panes — so the app's monospace face changes depending on which page you are looking at.

C6Spacing — no grid

Across the workspaces there are 20 distinct setContentsMargins tuples and seven setSpacing values. The dominant card padding (16, 16, 16, 16) is used 37 times, which is the good news; the other 19 variants — (20,16,16,16), (16,14,16,14), (18,10,18,16), (12,8,12,8), (8,4,8,8) — are each used once or twice with no rule behind them.

Spacing splits 18×8, 17×10, 9×12, 8×6, 8×4. The 6s and 10s put the app off any consistent 4- or 8-point rhythm, and there are no named constants to reach for — gui/themes/effects.py exports radius constants (R.button, R.card, R.input) but no spacing scale.

Recommended direction

One recommendation, stated plainly, plus the two alternatives and why they lose.

Adopt the Indexer page as the standard, and make the system mandatory rather than available. Do not design a new look. The target is already shipping, already themed across 14 palettes, and already the page users meet first. The work is enforcement and migration, not invention.

Name it “Workbench”: every workspace is a hero card stating what the tool does, a stepper stating the workflow, titled cards for each stage, and exactly one primary action in a bordered action bar. Preview-first is the project's core architectural rule; the stepper is that rule made visible, which is why this direction fits AlphaDEX specifically rather than being generic tidiness.

Why not a fresh visual direction?

Because nothing here is ugly — it is inconsistent. The token layer, the custom painter and the 14 themes represent real, working investment. A restyle would discard that and leave the same structural problem: twelve pages that each invent their own layout. Consistency is the deliverable; a new palette would not produce it.

Why not standardise on Utilities instead?

It is tempting — Utilities is the only page that reads tokens, and its tile-and-pill treatment is attractive. But it suits a launcher of small independent actions, which is what that page is. It does not suit the eight pages that are long-running, multi-stage, preview-then-execute workflows. Take its status pill and icon tile into the shared library; do not take its page layout.

What the vocabulary is missing

Four gaps explain most of the ad-hoc styling. Close these and the escape hatches lose their reason to exist:

  • A secondary / ghost button. Only primaryBtn, dangerBtn and successBtn exist, so every toolbar and mode control falls back to neutral or rolls its own — Graph's eight buttons, Player's transport, Help's full-width rows.
  • A status pill. Utilities built one; Tag Fixer, Compression and Library Sync each hand-colour a plain label instead.
  • A spacing scale. effects.py exports radii but no spacing, so 20 margin variants accumulated. Add S.xs/sm/md/lg beside R.
  • Reachable tokens. Give WorkspaceBase a self.tokens property and a _on_theme_changed() hook. Today a workspace must import the manager by hand, which is precisely why twelve of them never bothered.

Decisions this settles

  • Commit actions are red, everywhere. Green marks completed state, not a button that writes to the library. Tag Fixer changes, not Duplicates.
  • One step idiom: the stepper rail. Genre Normalizer's numbered headings become a stepper; the wizard's counter stays (it is a genuine modal sequence) but adopts the accent.
  • Icons are icons, not label text. Strip emoji from button and tab strings; pass a QIcon.
  • Phases are steps. Retire “Phase A/B/C” in favour of the step numbers already shown above it.
  • The log drawer stays dark in light themes — but gets a deliberate console treatment so it reads as a choice.

Migration plan

Ordered so that each phase is independently shippable and the early phases make the later ones mechanical. Phases 0–2 are the ones worth doing regardless of which direction you pick.

PHASE 0

Fix the eight defects

Independent of any design decision. D1 and D2 are two-word fixes that currently break tab labels, group-box titles and an entire dialog; D3–D5 are contrast bugs that make three surfaces unreadable; D7 and D8 are layout clipping.

  • D1 and D2 are already applied in this branch — they had to be, to capture the screenshots above. The rest are listed with line numbers in Defects.
PHASE 1

Close the escape hatches

No visual change; this is the step that makes everything after it cheap.

  • Change status_changed to carry a semantic level, not a hex. Deletes ~30 hardcoded colours across 11 files by itself.
  • Add self.tokens and a theme hook to WorkspaceBase.
  • Add secondaryBtn / ghostBtn to the painter and a StatusPill widget lifted from Utilities.
  • Add a spacing scale to effects.py.
  • Add a CI grep that fails on a new hex literal or font-size: outside gui/themes/. Without this the drift returns.
PHASE 2

Delete what nobody sees

Three files carry styling that no user can reach, and every one of them is a place future drift can hide.

  • gui/qt_launcher.py — 698 lines, 47 stylesheets, 45 colours, reachable only from the legacy Tkinter app.
  • gui/workspaces/clustered.py — a complete second Clustered page that is never routed to.
  • gui/theme.py — a shim whose build_stylesheet() returns "".
PHASE 3

Migrate the eight bare-title pages

Compression, Similarity, Tag Fixer, Genre Normalizer, Playlists, Clustered, Music Graph, Help. Each gets a hero card, a stepper where it has stages, titled cards, and one action bar. Largely mechanical after Phase 1. Start with Compression — 448 lines, a clear three-stage workflow, and it exercises every new component once.

PHASE 4

Player, Utilities, dialogs

The three that need judgement rather than mechanics.

  • Player keeps its full-bleed layout — that exception is legitimate — but every colour moves to tokens. Largest single job in the app at 1,980 lines.
  • Utilities keeps its tiles; they get promoted into the shared widget library so other pages can use them.
  • Dialogs adopt workspaceCard and the button vocabulary. Scan Engine and Bucketing POC already show the target shape.
PHASE 5

Re-run this audit

The capture harness used here is reproducible — it drives the real app under xvfb-run, walks every workspace and sub-tab, and writes 51 PNGs. Wiring it into CI turns this document into a regression check rather than a one-off.
